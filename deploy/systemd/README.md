# Capability Mesh — systemd drop-ins

The base unit `asg-capability-mesh.service` is generated by
`scripts/install-asg-capmesh-tailnet-service.sh` and installed at
`/etc/systemd/system/asg-capability-mesh.service` on the authoritative node (the sole
authoritative production server) and on the fallback non-voting member. Node
role is provisioned in the production env; the fallback node serves local low-latency reads
but rejects authoritative writes. It runs the service inside a network-sandboxed
`IPAddressDeny=any` / `IPAddressAllow=<specific CIDRs>` confinement.

These drop-in files in `*.service.d/` extend that base unit without editing
it directly, and are **not** managed by the installer script — they must be
copied to the host by hand (or by a future installer update) and are tracked
here so they survive any redeploy or host rebuild.

## Files

| File | Purpose |
|---|---|
| `entra-network-allow.conf` | Allows outbound to Microsoft Entra ID (`login.microsoftonline.com`) so the M365 device-code/browser/poll/token-exchange auth paths work under the network sandbox. |
| `google-network-allow.conf` | Allows outbound to Google's OAuth/OIDC endpoints (`oauth2.googleapis.com`, public-cert/JWKS) so `/api/v1/auth/google/callback` works under the network sandbox. Without this, Google sign-in fails with "Network is unreachable" even though the auth code path is fully implemented. |
| `restart.conf` | `Restart=always` (not just `on-failure`) plus a widened `StartLimitIntervalSec`/`StartLimitBurst`, so a clean-exit SIGHUP (used by the refresh timer to trigger reindex), a crash, or a failed deploy always brings the service back instead of leaving it `inactive`/`failed`. |
| `wal-checkpoint.conf` | Sets `CAPMESH_WAL_CHECKPOINT_SEC=120` so the SQLite WAL file is checkpointed periodically instead of growing unbounded. |

## Installation on a fresh host

```bash
sudo mkdir -p /etc/systemd/system/asg-capability-mesh.service.d
sudo cp deploy/systemd/*.conf /etc/systemd/system/asg-capability-mesh.service.d/
sudo systemctl daemon-reload
sudo systemctl restart asg-capability-mesh.service
```

Verify the network-allow ranges are still correct before relying on them —
Microsoft and Google can change DNS resolution within their published
prefixes; re-derive periodically (see the comments in each `.conf` file for
how the ranges were obtained).

## Why drop-ins, not edits to the base unit

The base unit is template-generated by
`scripts/install-asg-capmesh-tailnet-service.sh` and re-applied on every
deploy. A `.service.d/*.conf` drop-in is additive (systemd merges it on top
of the base unit) and is never touched by the installer's
`find ... -delete && tar -xzf` step against `$REMOTE_CODE`, so it survives
the autodeploy GitHub Actions workflow without modification to the
installer script itself.
